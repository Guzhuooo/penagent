Conclusions used by the implementation:

- `import('fs')` and `import('process')` work in QuickJS; the `process` module exposes
  Promise `exec(file, args, options)` returning `{code, signal, stdout, stderr}`.
  It is execFile-like: the first argument is an executable path, not a shell line.
- There is no fs write API on this firmware. Writing is done by running
  `/bin/sh -c "printf '%s' <quoted content> > <quoted path>"` through
  `process.exec` (async, with stdout/stderr/exit code) and then verifying with `fs`.
  `Global.execShell` (synchronous boolean, ~3 ms) remains as a fallback when the
  process module is unavailable; fs read-back is the durability check in both cases.
- `$workspace` is the app slot directory (`.../pkg/<appid>/<slot>/`). The workspace
  root is derived as `<appid dir>/data/penagent-workspace`, which survives slot
  replacement on update. `/userdata/...` is writable by the runtime and shell.
- `fs.readdir` returns an array of file-name strings; `fs.stat` returns a `mode`
  whose file type bits distinguish 0o040000 (dir) and 0o100000 (file); `fs.rm`
  removes files and empty directories; `fs.readFile` returns the text as a string
  (wrapped as `{result}` in some paths and unwrapped in others, hence normalization).
- `/bin/timeout` exists (busybox), so every command/file execution is wrapped with
  a hard wall-clock bound. `process.exec`'s own `timeout` option was observed to be
  coarse (killed after ~1 s for a 300 ms value), which is why the shell-level
  `/bin/timeout` wrapper is used for the product path.
- No `.so`, no native JSAPI and no C/C++ build is involved in this capability.
